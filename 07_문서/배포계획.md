# 배포 계획 — SecuGen-Prism (PostgreSQL 전환 + 신규 도메인)

## ✅ 확정 (2026-08-20) — 무료·국내·상시가동
사용자 요구: **무료 + 한국 서버 + 로컬 PC 탈출**. 조사 결과 확정 스택:
```
Oracle Cloud Always Free  (춘천/한국 리전, 평생무료, 데이터 국내)  — VM 한 대에 전부
├─ PostgreSQL (직접 설치)
├─ 앱 (systemd 상시가동)
└─ Caddy (HTTPS 자동)  ←  secugen-prism.secugen-logistics.com (서브도메인=무료)
   * Cloudflare = 무료 DNS 로만, 터널 불필요 (VM 공인 IP 직접)
```
- **무료 한국 서버**: Oracle Always Free 춘천 리전(AWS 1년제와 달리 평생무료). ARM(4C/24GB)
  춘천 재고부족 시 소형 x86(1C/1GB)도 무료 — 이 앱엔 충분. 가입은 본인확인용 해외카드 필요(청구X).
- **도메인 무료**: 이미 가진 secugen-logistics.com 의 **서브도메인**이 무료. 독립도메인은 유료(연 1~2만).
- 님 할 일: Oracle 계정·VM 생성, DNS A레코드. 내 할 일: 앱 PG포팅, 배포 스크립트(설치/systemd/Caddy).

> 한국 리전/사내 서버에 둘지 **보안정책 확인**이 먼저입니다.

## 1. 호스팅 3가지 안 (어디서 돌릴까)

| 안 | 방식 | 장점 | 단점 | 비용 |
|---|---|---|---|---|
| **A. 로컬 유지 + 터널** | 지금 PC에서 실행, 터널로 노출 | 이전 작업 거의 0 | **PC 꺼지면 중단**, 회사망 의존 | 무료 |
| **B. 클라우드 VPS + Caddy** ⭐ | 리눅스 서버 상시가동, Caddy 자동 HTTPS | 표준·안정·상시가동, **Cloudflare 불필요** | 서버 관리 필요 | 무료~$5/월 |
| **C. PaaS (Render/Railway/Fly)** | 앱+PG를 플랫폼에 배포 | 운영 최소, PG 포함 | stdlib 서버 약간 수정, 데이터 해외 | 무료티어~ |

**추천: B (VPS + Caddy)** — "제대로 된 서버 배포" 취지에 맞고 상시가동. Caddy가 Let's Encrypt로
HTTPS 자동발급이라 **Cloudflare 없이** 표준 방식으로 됩니다. 회사 데이터면 **한국 리전 VPS**
(Naver Cloud / Gabia / Cafe24) 고려, 글로벌이면 Oracle Cloud(무료티어)·Vultr·DigitalOcean.

### Cloudflare "대안" 조사 요약 (2026)
- **로컬 노출 터널류**: Cloudflare Tunnel(무료·현재) / **Tailscale Funnel**(WireGuard 메시, 간단·안전) /
  **frp**(오픈소스 자체호스팅, 강력·회사서버에 적합) / ngrok·Pinggy(즉시 공유용).
- **VPS 직접 노출**: **Caddy** 또는 Nginx + Let's Encrypt → 터널 자체가 불필요(가장 표준).
  → 즉 B안으로 가면 "Cloudflare를 대체"하는 게 아니라 **터널이 아예 필요 없어집니다.**

## 4. 앱 PostgreSQL 전환 (내가 할 코드 작업)
현재 백엔드는 `sqlite3` 직접 호출. 아래로 포팅:
- **DB 추상화 계층 신설**: 환경변수 `DATABASE_URL` 있으면 PostgreSQL(psycopg), 없으면 SQLite(개발).
- 플레이스홀더 `?`→`%s`, `INSERT OR IGNORE`→`ON CONFLICT DO NOTHING`,
  `AUTOINCREMENT`→IDENTITY, `GENERATED ... VIRTUAL`→STORED(스키마는 이미 완료), 커넥션/트랜잭션.
- `self_check.py`(90 검사)로 SQLite 회귀 + PG 연결 후 동일 검증.
- ⚠️ 이 환경엔 PG 서버가 없어 **PG 경로 최종검증은 실제 PG 연결 후** 가능(그래서 듀얼지원으로 안전하게).

## 6. 실행 순서(제안)
1. **(내가)** 앱 PG 듀얼지원 포팅 + SQLite 회귀검증 → GitHub 푸시(님)
2. **(님)** VPS 생성 + 도메인/DNS + PG 설치
3. **(님+나)** 배포: schema/data 적재 → 앱 systemd 등록 → Caddy HTTPS
4. 검증 → 신규 도메인으로 전환, 기존 터널은 백업으로 유지 후 정리
